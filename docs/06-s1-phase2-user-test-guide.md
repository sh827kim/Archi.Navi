# S1 Phase 2 사용자 테스트 가이드

> 작성일: 2026-03-29
> 대상 범위: `S1-7 Dashboard Home`, `S1-8 Empty State 가이드`, `S1-9 사이드바 접기/펼치기`
> 기준 브랜치: `feature/s1-phase2`

---

## 1. 테스트 목적

이번 테스트는 워크스페이스 진입 경험과 빈 화면 안내, 그래프 화면의 가용 폭 개선이 실제 사용자 흐름에서 자연스럽게 동작하는지 확인하는 데 목적이 있다.

---

## 2. 사전 조건

1. 웹 앱이 실행 중이어야 한다.
2. 테스트용 브라우저의 localStorage가 비정상 상태가 아니어야 한다.
3. 아래 두 종류의 워크스페이스가 있으면 가장 좋다.
   - 데이터가 거의 없는 신규 워크스페이스
   - 기존 데이터가 있는 워크스페이스

권장 실행:

```bash
pnpm dev
```

---

## 3. 테스트 시나리오

### 시나리오 1. 기존 워크스페이스 선택 시 홈으로 진입

목적: 워크스페이스 선택 기본 진입 경로가 `/home`으로 바뀌었는지 확인한다.

절차:
1. `/workspaces`로 이동한다.
2. 기존 워크스페이스 하나를 선택한다.
3. 첫 진입 화면을 확인한다.

기대 결과:
- `/home`으로 이동한다.
- 상단에 `운영 요약` 제목이 보인다.
- 좌측 사이드바에 `홈` 메뉴가 활성화된다.

### 시나리오 2. 신규 워크스페이스 온보딩 완료 시 홈으로 진입

목적: 온보딩 종료 후 더 이상 빈 그래프가 첫 화면으로 나오지 않는지 확인한다.

절차:
1. `/workspaces/new`로 이동한다.
2. 워크스페이스 이름을 입력한다.
3. `추론 설정`, `레이어`, `태그` 단계를 기본값으로 진행한다.
4. `코드 스캔` 단계에서 `건너뛰고 완료`를 누른다.

기대 결과:
- 완료 후 `/home`으로 이동한다.
- 생성한 워크스페이스 이름이 홈 화면 제목에 반영된다.
- 최근 추론 실행 empty state와 빠른 액션이 보인다.

### 시나리오 3. Dashboard Home 운영 요약 확인

목적: 홈 화면이 단순 랜딩이 아니라 운영 개요를 제공하는지 확인한다.

절차:
1. 데이터가 있는 워크스페이스로 `/home`에 진입한다.
2. 요약 카드와 우측 빠른 액션 영역을 본다.

기대 결과:
- `총 Object`, `서비스`, `도메인`, `승인 대기` 카드가 보인다.
- `최근 추론 실행` 목록 또는 empty state가 보인다.
- 빠른 액션에 최소 다음 항목이 보인다.
  - `추론 실행`
  - `코드 스캔`
  - `승인 이동`

### 시나리오 4. Dashboard Home 빠른 액션 이동 확인

목적: 홈 화면에서 바로 다음 작업으로 이동할 수 있는지 확인한다.

절차:
1. `/home`에서 `추론 실행`을 누른다.
2. 다시 `/home`으로 돌아와 `코드 스캔`을 누른다.
3. 다시 `/home`으로 돌아와 `승인 이동`을 누른다.

기대 결과:
- `추론 실행` 클릭 시 `/approval`로 이동한다.
- `코드 스캔` 클릭 시 `/settings`로 이동하고 코드 스캔 탭으로 진입할 준비가 된 화면을 본다.
- `승인 이동` 클릭 시 `/approval`로 이동한다.

### 시나리오 5. 사이드바 접기/펼치기 확인

목적: 그래프 탐색용 좁은 모드가 정상 동작하는지 확인한다.

절차:
1. `/home` 또는 `/architecture`에서 사이드바 접기 버튼을 누른다.
2. 아이콘 모드 상태를 확인한다.
3. 같은 탭에서 새로고침한다.
4. 다시 펼치기 버튼을 누른다.

기대 결과:
- 접기 후 사이드바 폭이 줄어들고 텍스트 라벨이 사라진다.
- 아이콘만으로도 현재 메뉴 active 상태가 구분된다.
- 새로고침 후에도 접힌 상태가 유지된다.
- 펼치기 후 기존 전체 메뉴 라벨이 다시 보인다.

### 시나리오 6. Architecture empty state 안내 확인

목적: 데이터가 없는 워크스페이스에서 다음 행동이 분명한지 확인한다.

절차:
1. 레이어 또는 서비스 데이터가 없는 워크스페이스를 선택한다.
2. `/architecture`로 이동한다.

기대 결과:
- `아직 레이어드 아키텍처를 그릴 데이터가 없습니다` 문구가 보인다.
- 아래 링크가 보인다.
  - `Object 목록 열기`
  - `설정으로 이동`

### 시나리오 7. Mapping Graph empty state 안내 확인

목적: 그래프가 비었을 때 사용자가 다음 단계로 이동할 수 있는지 확인한다.

절차:
1. Object 또는 승인 데이터가 부족한 워크스페이스를 선택한다.
2. `/mapping-graph`로 이동한다.

기대 결과:
- `현재 레벨에 표시할 Object Mapping이 없습니다` 문구가 보인다.
- 아래 링크가 보인다.
  - `Object 목록 열기`
  - `승인 대기로 이동`

### 시나리오 8. Approval empty state 안내 확인

목적: 후보가 없을 때도 사용자가 막히지 않는지 확인한다.

절차:
1. 승인 후보가 없는 워크스페이스를 선택한다.
2. `/approval`로 이동한다.
3. 기본 `관계 후보` 탭과 `도메인 후보` 탭을 각각 본다.

기대 결과:
- 관계 후보 탭에서 `승인 대기 중인 관계 후보가 없습니다` 문구가 보인다.
- 링크 `Object 목록 열기`, `추론 이력 보기`가 보인다.
- 도메인 후보 탭에서 `승인 대기 중인 도메인 후보가 없습니다` 문구가 보인다.
- 링크 `Object 목록 열기`, `홈으로 이동`이 보인다.
- 각 탭에서 추론 실행 버튼은 계속 노출된다.

### 시나리오 9. 커맨드 팔레트 홈 이동 확인

목적: 전역 탐색 경로에도 홈이 반영됐는지 확인한다.

절차:
1. 아무 대시보드 화면에서 `Cmd+K` 또는 `Ctrl+K`를 연다.
2. `홈`을 검색하거나 목록에서 선택한다.

기대 결과:
- 커맨드 팔레트 결과에 `홈` 항목이 보인다.
- 선택 시 `/home`으로 이동한다.

---

## 4. 테스트 중점 체크포인트

- 홈 진입이 일관되게 `/home`으로 수렴하는가
- 사용자가 데이터가 없는 상태에서도 다음 행동을 즉시 알 수 있는가
- 사이드바 접기 상태가 세션 중 일시적이 아니라 유지되는가
- 홈 화면이 단순 소개 페이지가 아니라 운영 시작점 역할을 하는가
