# 55. Light Theme Tone Refresh SPEC

- 상태: Current
- 작성일: 2026-04-05

## 배경

현재 라이트 모드는 순백 배경과 보라 포인트 컬러 비중이 높아서 장시간 사용 시 눈부심이 강하다. 또한 아키텍처 뷰와 Object Mapping 뷰 일부는 다크 전용 색을 직접 사용하고 있어, 라이트 모드에서도 흰 텍스트나 어두운 배경이 그대로 남는다.

## 목표

- 라이트 모드를 더 편안한 톤의 오프화이트 기반으로 조정한다.
- 전역 포인트 컬러를 보라 계열에서 벗어난 청록 중심 계열로 재정의한다.
- 다만 그래프 노드/엣지 팔레트는 기존의 높은 식별성을 유지할 수 있다.
- 아키텍처 뷰와 Object Mapping 뷰가 현재 테마에 맞는 배경/라벨/텍스트 색을 사용해야 한다.

## 요구사항

### 1. 전역 라이트 테마 토큰

- `background`, `card`, `popover`, `sidebar-bg`는 순백이 아닌 약간 따뜻한 오프화이트 계열이어야 한다.
- `primary`, `ring`, `accent-foreground`는 보라가 아닌 청록 계열이어야 한다.
- 라이트 모드 body는 완전 단색 대신 매우 약한 배경 질감을 허용한다.

### 2. 아키텍처 뷰

- 라이트 모드에서 layer title 텍스트는 어두운 글자색을 사용해야 한다.
- tag badge와 layer band, object node color는 라이트 모드에서도 과도하게 어둡지 않아야 한다.
- object node text color는 node 배경색 대비를 기준으로 읽기 가능해야 한다.

### 3. Object Mapping 뷰

- 3D 그래프 배경은 현재 테마를 따라야 한다.
- 라이트 모드에서 label surface와 link label 배경은 밝은 중성 톤이어야 하며, 텍스트는 어두운 색이어야 한다.
- 뷰 탭과 node/edge palette는 기존 vivid graph palette를 유지해도 된다.

### 4. 회귀 방지

- 라이트 모드 palette 적용 여부를 테스트로 검증해야 한다.
- RollupGraph는 현재 테마를 하위 3D 그래프에 전달해야 한다.

## 비범위

- 사용자별 커스텀 테마 생성
- 다크 모드 전체 색상 체계 재설계
- 레이어별 수동 색상 입력 UX 변경

## 검증

- 라이트 모드에서 아키텍처 뷰의 레이어 제목/태그 스타일이 다크 고정 색을 사용하지 않아야 한다.
- 라이트 모드에서 Object Mapping 뷰가 다크 배경색을 유지하지 않아야 한다.
- 포인트 색상 변경 이후 주요 탭/버튼 active 상태가 새 primary 색을 사용해야 한다.
